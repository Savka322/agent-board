# agent-board
![Uploading agent-board-demo.gif…]()

[English](README.md)

Локальная канбан-доска для агентов, которые пишут код. Каждый запуск агента идёт через карточку задачи. Видно, кто из агентов что делает прямо сейчас и что кого держит. У каждого запуска остаётся история: карточка, круги доработки, отчёт и итог.

- **Оркестратор** — Claude Code со скиллом `agent-board` из этого репо. Режет эпик на карточки, стартует каждый запуск, читает каждый дифф, гоняет тесты и сливает.
- **Исполнители** — Codex CLI. Каждая задача идёт в своей рабочей копии git и своей ветке.
- **Вы** смотрите доску в браузере, отвечаете на вопросы, которые передал оркестратор, и одобряете итоговое слияние.

> **Ранняя версия, сначала Windows.** Сделано и проверено на Windows 11. Ограничитель памяти (Job Objects) и уведомления пока работают только на Windows.

> **Агенты пишут код в ваш репозиторий.** Доска работает в своих рабочих копиях и локальных ветках `agent/*` и `epic/*`. Файлы вашей рабочей копии она не трогает и никогда не пушит. И всё же берите репозиторий, у которого есть резервная копия, и читайте то, что сливаете.

## Что проверяет код

Правила живут в коде, а не в промпте:

- **Нет карточки — нет запуска.** Codex стартует только через `agentctl start` или `agentctl resume` по карточке.
- **Границы задачи.** `accept` отказывает, если дифф трогает файлы вне `allowed_files` карточки. Исключение — оркестратор записывает причину.
- **Не больше 3 запусков на задачу.** Дальше карточку надо перерезать.
- **Вопросы.** Исполнитель, который не уверен, останавливается с вопросом. Оркестратор отвечает сам или передаёт вопрос вам. Задачи, которые стоят на том же решении, ждут вашего ответа.
- **Бюджет памяти.** Тесты и агенты делят один потолок (по умолчанию 16 ГБ), у каждого запуска своё задание Windows (Job Object). Нехватка памяти показывается как `oom`, а не как красный тест.
- **Одобрение слияния.** Ветка эпика попадает в основную ветку только после кнопки «Одобрить слияние» на доске. `epic merge` никогда не пушит и не сливает в рабочую копию с незакоммиченными правками.

## Что нужно

- Windows 10 или 11
- [Bun](https://bun.sh) 1.4+
- Git 2.38+
- [Codex CLI](https://github.com/openai/codex) 0.159+, вход выполнен (`codex login`)

## Установка

```bash
git clone https://github.com/Savka322/agent-board.git
cd agent-board
bun install
bun run web:build
```

Проверьте, что машина умеет всё, что нужно доске: отсоединённые процессы, остановку дерева процессов, Job Objects, уведомления и SQLite. Проверка покажет одно тестовое уведомление.

```bash
bun probes/run-all.ts
```

Поставьте скилл оркестратора для Claude Code. Он ляжет в `~/.claude/skills/agent-board`, с путём к этой папке внутри:

```bash
bun run agentctl install-skill
```

По желанию — своё имя приложения для уведомлений Windows. Без него уведомления приходят от имени PowerShell. Команда пишет один ключ реестра в `HKCU`, `notify uninstall` его удаляет.

```bash
bun run agentctl notify install
```

## Быстрый старт

**1. Запустите доску** и не закрывайте терминал:

```bash
bun run agentctl serve
```

Откройте http://127.0.0.1:8790.

**2. Опишите проект** в `~/.agent-board/projects/<name>.toml`:

```toml
name = "shop"
repo = 'D:\code\shop'
base_branch = "main"
light_tests = ["bun test --bail"]                  # исполнитель может гонять их сам
gates = [{ cmd = "bun test", ram_est_gb = 2 }]     # их гоняет только оркестратор, под бюджетом памяти
data_links = [{ from = 'D:\code\shop\node_modules', to = "node_modules", mode = "link" }]
rules = ["TypeScript strict. Follow the existing style."]

[executor]
kind = "codex"
model = "<codex model id>"
effort = "high"
sandbox = "workspace-write"
extra_config = []
```

Все поля описаны в [справке по профилю](skills/agent-board/references/profile.md).

У исполнителей нет сети, поэтому зависимости проекта поставьте заранее. В рабочей копии только файлы под git; папки вроде `node_modules` подключайте через `data_links`.

Зарегистрируйте профиль:

```bash
bun run agentctl project add shop
```

**3. Отдайте эпик.** Откройте Claude Code в своём проекте и скажите, что нужно:

> Раздай эпик: повторять неудачные доставки вебхуков с нарастающей паузой.

Дальше работает скилл. Он покажет карточки и дождётся вашего «да». Потом запустит исполнителей, проверит их работу и вынесет вопросы на доску. Когда все задачи готовы, нажмите на доске **«Одобрить слияние»**.

## Без Claude Code

`agentctl` — обычный CLI, цикл можно вести руками. `bun run agentctl --help` выводит все команды. Формат карточки — в [шаблоне карточки](skills/agent-board/references/card-template.md).

```bash
bun run agentctl epic new shop PAY "Webhook retries"
bun run agentctl task add PAY cards/PAY-1.md
bun run agentctl task promote PAY-1
bun run agentctl start PAY-1
bun run agentctl wait --for review
bun run agentctl review PAY-1
bun run agentctl gate PAY-1
bun run agentctl accept PAY-1
```

Когда все задачи готовы и вы одобрили слияние на доске:

```bash
bun run agentctl epic merge PAY
```

## Как это устроено

Колонки: Отменено, К выполнению, Next, В работе, Ревью, Нужен ваш ответ, Готово.

```text
todo --promote--> next --start--> running --run ends--> review --accept--> done
                                     ^                    |
                                     +---- resume --------+   замечания ревью, не больше 3 запусков
                   next <-- answer -- needs_owner <-------+   вопрос передан вам
                   todo <-- reject -----------------------+   карточка была неверной
```

- `agentctl serve` — диспетчер и веб-доска в одном процессе. Диспетчер считает, какие задачи можно стартовать, следит за запусками и будит оркестратор через `agentctl wait`. Сам он ничего не стартует.
- Каждый запуск — отдельный отсоединённый процесс, поэтому перезапуск `serve` агентов не убивает. Сырой поток Codex хранится рядом с живым логом, который виден на доске.
- В песочнице Codex коммитить нельзя. `accept` сам коммитит правки исполнителя и вливает их `--no-ff` в ветку эпика.

## Где что лежит

| Что | Где |
|---|---|
| База, логи запусков, карточки | `~/.agent-board/` (другое место — через `AGENT_BOARD_HOME`) |
| Профили проектов | `~/.agent-board/projects/<name>.toml` |
| Рабочие копии задач | `~/.agent-board/worktrees/<project>/<task>/`, ветки `agent/<task>` |
| Установленный скилл | `~/.claude/skills/agent-board/` |

## Настройки

`bun run agentctl settings` показывает их, `--set key=value` меняет одну.

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `max_slots` | 5 | Сколько исполнителей работает одновременно |
| `memory_limit_gb` | 16 | Общий потолок памяти для тестов и агентов |
| `executor_memory_gb` | 2 | Доля потолка на каждого работающего агента |
| `stale_minutes` | 10 | Сколько минут тишины, прежде чем запуск помечается «завис?» |
| `web_port` | 8790 | Порт веб-доски |

## Безопасность

- Веб-сервер слушает только `127.0.0.1`. Каждая запись требует токен, выданный при запуске, и правильный `Origin`, поэтому другие страницы в браузере не могут ничего отправить на доску.
- Исполнители работают в песочнице Codex `workspace-write` без доступа к сети.

## Ограничения

- Пока только Windows. Для других систем нужны свой ограничитель памяти (например, cgroups на Linux) и свои уведомления; интерфейсы для них есть.
- Один вид исполнителя: Codex CLI.
- Упор в лимит подписки определяется эвристикой по тексту ошибки Codex.
- Один пользователь на одной машине.
